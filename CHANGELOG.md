- **Indonesia (`ID`) — a new jurisdiction serving `CompanyResolve`, `CompanyFilings`, and `CompanyFinancials` from IDX, the first national-exchange source here whose financials come from real XBRL rather than a PDF.** New `src/adapters/idxIndonesia.ts` drives the Indonesia Stock Exchange's keyless `www.idx.co.id/primary/…` endpoints, implementing the live-verified [`SEASIA-TRIAGE.md`](SEASIA-TRIAGE.md) §1 finding, which ranked Indonesia the single best first build of the five SE Asian markets.
  - **`CompanyFinancials` is the standout, and it is genuinely structured.** IDX ships an **`instance.zip`** (plain XBRL, IDX 2020 `idx-cor` taxonomy) with every financial-report submission, alongside the inline-XBRL package, the spreadsheet and the English/Indonesian PDFs. The adapter downloads that instance with the existing zero-dep zip machinery (`src/core/zip.ts`) and extracts revenue, profit from operations, profit attributable to owners of the parent, total assets and total equity in **IDR** — current period plus the comparative prior year — reusing the shape of the JP EDINET XBRL path. Concepts are matched by **XML local name** so any taxonomy year or prefix variant resolves; only **undimensioned** period contexts qualify (IDX names dimensioned ones `CurrentYearInstant_3410000_NonControllingInterestsMember`, so a per-component figure can never surface as a company total); **units are honoured**, so the divide-based `IDRPerShares` unit used for EPS is excluded and a per-share figure can never be mistaken for a statement total; the consolidation **basis is read from the filer's own dei declaration** (`WhetherTheFinancialStatementsAreOfAnIndividualEntityOrAGroupOfEntities`), since IDX — unlike EDINET — does not file both bases side by side; and the revenue concept lists the general-industry element ahead of the banking/financing variants, because **a bank files no `SalesAndRevenue`** and reports `TotalInterestAndShariaIncome` instead. Verified live through the built artifact (FY2025 audited): **TLKM** revenue Rp 146,742,000,000,000 / assets Rp 287,759,000,000,000 / equity Rp 130,685,000,000,000, and **BBCA** interest+sharia income Rp 98,912,652,000,000 / assets Rp 1,586,828,536,000,000 / equity Rp 281,466,478,000,000 — both consolidated, with the prior comparative year alongside, and BBCA exercising the banking revenue variant.
  - **The browser-fetch tier, handled the way BSE India already is.** `www.idx.co.id` is **anti-bot protected**: a plain request answers `403` with a Cloudflare/Imperva challenge shell (re-verified live 2026-08-29), while the same paths serve full JSON to a browser-class client. This is the BSE India tier, not the fatal SGX/ASX block, so the adapter is built **inject-friendly**: it sends realistic browser headers on the default fetch and works outright wherever the edge lets those through, and where the edge refuses it raises a typed **`IdxBlockedError`** whose message names the escape hatch (`inject a browser-backed fetchFn via AdapterOptions`) and states in terms that **this is NOT an empty result for the issuer**. That distinction is the point: a refusal and an absence of disclosure look identical to a caller unless the library keeps them apart. A blocked instance **download** propagates rather than degrading to a link, because a transport refusal is not evidence about the filing. Both the degraded path (no `fetchFn`, from this network) and the working path (with one supplied) were verified live through the built artifact.
  - **`CompanyResolve`** covers all ~965 listed emiten on the Main / Development / Special Monitoring boards — 4-letter ticker (`kode emiten`, carried in `sourceIdentifiers`), legal name, sector/subsector, listing board and listing date — resolving by exact ticker (server-side filtered) or by issuer name against the full roster. **`CompanyFilings`** returns per-issuer disclosure announcements (*pengumuman*), date-windowed and limited, each linking the announcement letter as filed — preferring the letter over its *lampiran* annexes.
  - **Honest fallbacks and honest limits.** `CompanyFinancials` never guesses: a submission carrying **no `instance.zip`**, or an instance tagging **none of the headline totals**, returns empty facts plus **the official report link and the reason**; no submission at all in the years scanned says so explicitly. `CompanyInsiders` and `CompanyOwners` are honest unsupported — director/commissioner detail and substantial-shareholder disclosure reach IDX as announcement PDFs and via the separate **KSEI** depository channel, not a clean feed — as is `PrivateRaises`. **AHU** (the national legal-entity registry) is a **paid PNBP per-document** product, so there is no free ID private-company resolve, and **OJK** is a regulator/licensing site rather than a filing store. - **Netherlands (`NL`) — a new jurisdiction serving `CompanyResolve`, `CompanyOwners`, and `CompanyInsiders` from the AFM's keyless disclosure-register exports.** New `src/adapters/afmRegisters.ts` reads three statutory registers via `https://www.afm.nl/export.aspx?type=<GUID>&format=csv|xml` — **substantial holdings** (*meldingen zeggenschap*, Wft ch. 5.3 → `CompanyOwners`), **Art. 19 MAR managers' transactions** and **directors'/commissioners' holdings** (both → `CompanyInsiders`) — with no key, login, or token.   - **Whole-file exports, reduced to a cached digest.** Verified live: the exports support **no server-side filtering** (an `?issuer=` parameter is silently ignored, returning a byte-identical file), **`Range` is not honoured** (the server replies 200 with the entire body), and the AFM register page links no smaller or "recent" variant — so a per-issuer view can only come from fetching a register and filtering client-side. The substantial-holdings CSV is **108,516,396 bytes / 293,488 rows** (the XML variant of the *same* register is 377,404,561 bytes, so CSV is deliberately preferred here even though XML is otherwise the safer parse). Each register is therefore reduced **at parse time** to a compact per-issuer digest and **only the digest is cached** (`AdapterOptions.cache`, **24 h TTL**, one key per register): collapsing the holdings register to the latest notification per (issuer, holder) — folding the two rows AFM writes per notification, one under `Kapitaalbelang` and one under `Stemrecht` — turns 293,484 data rows / 108 MB into **2,415 records / ~0.39 MB** across 133 issuers, a ~265× reduction. The raw export is never persisted.
  - **First-call cost, honestly.** Measured end-to-end through the built server: ASML `CompanyOwners` **cold 28.8 s, warm 7 ms**; `CompanyInsiders` (two XML registers, ~14 MB) ~6 s cold. Like the BR/CVM adapter, **the first NL call in a session can be slow** — supply a cache so the digest survives process restarts, or a per-request-process deployment re-downloads 108 MB each time. `CompanyInsiders` never touches the holdings register.

All three emit `structuredContent` (`ownersStructured` / `insidersStructured` / `entitiesStructured`, tagged `NL`) and `_Next:_` trailers.
  - **Issuer disambiguation.** A verbatim legal-name query wins outright over normalized matching (name folding drops `Holding`, so `Heineken Holding N.V.` would otherwise tie with `Heineken N.V.` and lose a tiebreak to the wrong issuer), and `CompanyInsiders` resolves the issuer **once against the union of both registers** rather than matching each separately — which would merge two different legal entities under one heading. Responses state which register issuer a loose query matched.

Encoding is handled per format (the CSV is **Windows-1252**, its `Reëel` column mojibaking if read as UTF-8; the XML is UTF-8), the CSV is split by index scan rather than regex (at 108 MB a backtracking pattern would dominate), and XML records are split with a depth-aware scan because each record **nests a second `<vermelding>`** as a display label that would truncate a lazy regex. 52 new offline tests (44 adapter + 8 tool-routing) with fixtures shaped from the real exports — the holdings fixture stored Windows-1252 as AFM serves it, via a new `loadFixtureBytes` helper, so the decoding path is genuinely exercised. ### Added

- **CN `CompanyOwners` — top-10 shareholders (前十名股东) from the periodic report.** `CompanyOwners` with jurisdiction `"CN"` now locates the issuer's **freshest** full periodic report of any kind (annual *and* quarterly both carry the table, so the newest disclosure wins rather than preferring the annual), downloads and CJK-space-normalizes its text, and parses the **前十名股东持股情况** table into holder name, 期末持股数量 share count, 比例 percentage and 股东性质 nature. The table is genuinely ragged — **column order varies by issuer** (Kweichow Moutai prints name → 报告期内增减 → 期末持股数量 → 比例 → 股东性质; CATL prints name → 股东性质 → 比例 → 期末持股数量 → 增减), a holder with no change carries one fewer numeric cell, and long names wrap across lines — so the parser is a **value heuristic keyed on cell shape, not position**: a CJK-leading non-header cell starts or continues a name, the value in `(0,100]` (preferring an explicit `%` or a fractional one, never a `0` no-change cell) is the percentage, and the largest remaining integer is the holding count. **Only rows where both a percentage and a share count matched are emitted** — an unreadable row is dropped, never guessed — so a holder absent from the output may still be in the filing. `thresholdRegime` is `"CN top-10 shareholders (periodic report, as published)"`, and the response states plainly that this is an **as-published point-in-time snapshot, not a live share register and not UBO tracing**, with state-owned and nominee/custodian holders (香港中央结算, 中国证券登记结算) shown exactly as printed. - Brazil CVM open-data adapter (`jurisdiction: "BR"`): keyless, backed by the whole-market CSV/ZIP snapshots at `dados.cvm.gov.br`. `CompanyResolve` reads the CVM registration feed (accepts a CVM registration code such as `4170` for Vale, or a company name; the CD_CVM padding gap between feeds is normalized, and the per-market-segment duplicate rows the feed ships are collapsed to one entity per company). `CompanyFilings` reads the per-year IPE disclosure index (2003+) and returns category/species/subject rows with direct CVM RAD download links. `CompanyFinancials` reads the annual DFP bundles and returns total assets, stockholders' equity, revenue, operating income, and net income — consolidated-when-filed, otherwise individual — in BRL, labelled by fiscal period end, with `ESCALA_MOEDA` (thousands) scaling applied and a later restatement superseding an earlier figure. The Latin-1 (ISO-8859-1) feeds are decoded accordingly, and the DFP year bundle is selectively inflated to only the balance-sheet/income-statement members. `CompanyInsiders`, `CompanyOwners`, and `PrivateRaises` under `BR` return an explicit unsupported-jurisdiction explanation (CVM discloses that data inside the Formulário de Referência and CVM 44 documents this release does not parse); `OwnershipChain` remains global via GLEIF. Adds `BRL` (R$) currency formatting.
