# Project audit — 13 September 2026

Audited revision: `cac6103` (`0.8.0`).

The project has substantial fixture coverage and useful source-specific caveats, but green tests currently overstate its guarantees around data integrity, bounded downloads, cache freshness, and package consumption. This audit reproduced 11 defects: two P1 findings and nine P2 findings. Fix the HTTP trust boundary and fabricated numeric zero before treating the HTTP deployment and normalized financial output as production-ready.

P1 means high priority; P2 means a material defect to address in the next hardening pass. Findings describe the checked source and controlled inputs, not observed production incidents.

## Validation and scope

- `bun test`: **1,096 pass, 0 fail**, 4,281 assertions across 40 files.
- `bun run typecheck`: passed. The compiler resolved by `bunx tsc` was **7.0.2**; it is not a declared project dependency.
- Built the current source into an isolated temporary directory and emitted declarations there. Both succeeded.
- Imported the fresh bundle using **Node v24.18.0**: version `0.8.0`, ten tools, no accidental stdio startup.
- Compiled an isolated consumer against the package's self-reference and freshly generated declarations: **failed with three TS2307 errors**.
- Reproduced ten behavioral defects using injected responses, a controllable cache clock, a temporary sentinel file, and a locally started HTTP server. The package compilation failure is the eleventh finding.
- Source review covered shared infrastructure, tool routing, document download/write paths, package exports, CI/release workflows, and representative financial/resolution implementations. Deeper parser review focused on SEC and ESEF financials; cache review included OpenDART, EDINET, CVM, and AFM.
- No credentialed live suite, upstream availability verification, browser DNS-rebinding exploit, dependency-advisory scan, or independent Node 18/20/22 execution was performed. This is not a line-by-line certification of all 35,814 lines of tool/adapter/core source.
- No implementation files were changed. Only this report and the audit plan were added. The existing untracked `.playwright-mcp/` directory was left alone.

## Findings

### 1. P1 — HTTP transport accepts arbitrary Host and Origin

**Location:** [src/serverHttp.ts:47](../src/serverHttp.ts#L47).

`StreamableHTTPServerTransport({})` leaves the installed SDK's DNS-rebinding protection disabled. The surrounding Node HTTP handler performs no Host or Origin validation either.

**Reproduction:** POST an MCP `initialize` request to the local `/mcp` endpoint with `Host: attacker.example` and `Origin: http://attacker.example`. The server returned **200** and a successful initialization response.

**Impact:** Binding to loopback does not enforce a trusted HTTP host. In a browser/network configuration permitting DNS rebinding, an attacker-controlled hostname can reach the local tool service. The service exposes server-configured upstream access and a PDF tool that writes to caller-selected paths. When bound to a public interface, it also provides no application authentication boundary. The reproduced fact is acceptance of untrusted headers; a complete browser exploit was not attempted.

**Fix:** Validate Host and supplied Origin before dispatch, with explicit allowed values for local and hosted deployments. Enable the SDK protection or equivalent application checks. Define the access-control boundary before exposing non-loopback deployments. Test rejection as well as successful MCP calls.

### 2. P1 — Missing ESEF values become financial zeroes

**Location:** [src/adapters/xbrlFilings.ts:391](../src/adapters/xbrlFilings.ts#L391).

`Number(fact.value)` coerces `null` and blank strings to zero. The following finiteness check accepts that zero as a valid reported amount.

**Reproduction:** Supply a `Revenue` fact with `value: null` and otherwise valid dimensions. `getEsefFinancials` returns `concept: "revenue", value: 0, unit: "GBP"`.

**Impact:** An unavailable value becomes an affirmative numeric statement in normalized financial output. It can also occupy the winning concept/period slot and displace usable comparative data.

**Fix:** Reject null, absent, blank, boolean, and nonnumeric values before conversion. Preserve the distinction between missing and genuine zero. Add parser cases for both.

### 3. P2 — SEC retrieval failures become false absence claims

**Location:** [src/adapters/secEdgar.ts:971](../src/adapters/secEdgar.ts#L971); the same pattern exists in `getSecInsiders` around line 693.

`getSecPrivateRaises` catches every document download error and continues. The tool receives an empty array without knowing that matching filings existed but could not be downloaded.

**Reproduction:** Return a submissions record containing one Form D, then return HTTP 403 for its XML. The tool responds successfully with **“No Form D filings found”** and no `isError` flag.

**Impact:** Transport/access failures, including rate-limit failures, are indistinguishable from absence. A partial fetch can also return incomplete results without a completeness notice. The response's general absence caveat does not disclose the actual failure.

**Fix:** Propagate operational errors or return explicit partial-result metadata and failed filing links. Never label an all-failed document retrieval as no matching filings. Exercise 403, 429, and mixed-success cases through the tool layer.

### 4. P2 — Response-body consumption outlives request timeouts

**Location:** [src/core/http.ts:34](../src/core/http.ts#L34), [src/core/http.ts:46](../src/core/http.ts#L46).

The shared `request` clears its abort timer once response headers arrive. `getJson`, `getText`, and `getBinary` consume the body afterward. The older redirect helper likewise returns a live response after clearing its timeout.

**Reproduction:** Return headers immediately and complete the response body after 60 ms. `getText(..., timeoutMs=10)` succeeds after approximately **62 ms**; its captured signal remains un-aborted.

**Impact:** A stalled or slow body can hold a lookup open far beyond the configured deadline. This affects many adapters, not only document routes.

**Fix:** Keep the timeout active through body consumption, release resources on every exit, and propagate cancellation to the body reader. Test delayed headers and delayed bodies separately. The newer bounded binary helper already demonstrates a suitable lifetime model.

### 5. P2 — Most document size caps are checked after allocation

**Location:** [src/adapters/hkexNews.ts:988](../src/adapters/hkexNews.ts#L988), [src/adapters/companiesHouse.ts:1015](../src/adapters/companiesHouse.ts#L1015), [src/adapters/secEdgar.ts:1195](../src/adapters/secEdgar.ts#L1195).

Many routes call `getBinary` or `response.arrayBuffer()` before checking actual byte length. Some inspect Content-Length first, but absent or inaccurate headers still permit full buffering.

**Reproduction:** Stream thirty 1 MiB chunks without Content-Length through `getHkexDocumentPdf`. It consumes all **30 MiB**, then rejects against the **25 MiB** cap.

**Impact:** The cap limits accepted output, not transfer or peak memory. Larger upstream responses and concurrent requests can exhaust memory. The same download-before-check pattern remains in multiple Asian document adapters; the newest India work has not been generalized across them.

**Fix:** Adopt incremental byte accounting and cancellation for every bounded document path, reusing the existing bounded redirect-aware helper where appropriate. Test actual bytes read/cancellation, not only that the final result throws.

### 6. P2 — PDF writes can destroy existing files despite their annotation

**Location:** [src/tools/index.ts:7030](../src/tools/index.ts#L7030), [src/tools/index.ts:7798](../src/tools/index.ts#L7798).

The PDF branches pass caller-controlled paths directly to `writeFile`, which truncates existing files. Every tool nevertheless advertises `destructiveHint: false`. Default filenames are also deterministic rather than uniquely allocated temporary files.

**Reproduction:** Create a temporary text file containing `KEEP ORIGINAL`, then call GB `CompanyDocument` in PDF mode with that path and an injected document response. The call succeeds and replaces the text with PDF bytes while retaining `destructiveHint: false`.

**Impact:** An agent can overwrite application/configuration/user files writable by the server account. This is particularly consequential when the same operation is exposed through HTTP. Repeated/default downloads can collide too.

**Fix:** Default to exclusive creation and unique temporary paths. Require an explicit overwrite contract if replacement is supported and make annotations truthful. For hosted mode, define a server-controlled download directory rather than exposing arbitrary filesystem destinations.

### 7. P2 — Netherlands PrivateRaises silently dispatches to SEC

**Location:** [src/tools/index.ts:5710](../src/tools/index.ts#L5710).

The schema accepts `NL`, but the enumerated non-US rejection branch omits it.

**Reproduction:** `PrivateRaises({company: "1", jurisdiction: "NL"})` issues `https://data.sec.gov/submissions/CIK0000000001.json` and returns a US Form D result.

**Impact:** An explicitly selected jurisdiction is ignored. A matching US entity can produce unrelated evidence; otherwise the user sees a misleading US miss or credential requirement.

**Fix:** Reject every explicit jurisdiction other than US by construction. Add a table-driven test across all accepted jurisdiction values that verifies unsupported routes make zero source requests.

### 8. P2 — Expired persistent caches are refreshed with stale process data

**Location:** [src/adapters/openDart.ts:333](../src/adapters/openDart.ts#L333). Equivalent lifetime patterns occur in EDINET `loadCodeList`, CVM `loadRows`, and AFM `loadRegister`.

After the supplied cache expires, loaders reuse a previously fulfilled module-level promise and write its old value back with a new TTL. Those promises have no freshness deadline.

**Reproduction:** Fetch an OpenDART entry named `Old Name` using `InMemoryCache` and a controllable clock. Advance the clock 48 hours while the fake source is ready to return `New Name`. The next lookup still returns `Old Name`; total downloads remain **one**.

**Impact:** Long-running stdio/HTTP servers do not refresh daily datasets as expected. They can also perpetuate stale data into shared caches used by newly started processes. CVM/AFM instances of this pattern affect disclosure data, not just company names.

**Fix:** Give process memoization the same expiry semantics as the persistent cache, or memoize only in-flight work. Test expiry through the adapter rather than only testing the cache class in isolation.

### 9. P2 — The published TypeScript interface requires undeclared consumer dependencies

**Location:** [package.json:55](../package.json#L55), [src/server.ts:2](../src/server.ts#L2), [src/core/toolDefs.ts:1](../src/core/toolDefs.ts#L1), [src/core/types.ts:1](../src/core/types.ts#L1).

JavaScript is bundled, but generated declarations retain imports from MCP SDK and Zod. Both packages are development dependencies, so installing the published package does not provide them.

**Reproduction:** Build and emit declarations into an isolated package directory, copy the manifest, then compile a consumer containing `import { createTools } from "disclosures"` with strict NodeNext resolution. Compilation reports three TS2307 errors for `zod`, SDK `types.js`, and SDK `server/mcp.js`. Importing the JavaScript bundle itself succeeds.

**Impact:** The advertised TypeScript-library use case fails in a clean consumer without separately installed packages or suppressed declaration checking. Repository typechecking misses it because those dependencies are available locally.

**Fix:** Either publish self-contained declarations or declare and document the required consumer dependencies. Choose explicitly how that interacts with the zero-runtime-dependency claim. Add an isolated packed-package consumer compile to release validation.

### 10. P2 — Same-period ESEF amendments can lose to older values

**Location:** [src/adapters/xbrlFilings.ts:291](../src/adapters/xbrlFilings.ts#L291), [src/adapters/xbrlFilings.ts:461](../src/adapters/xbrlFilings.ts#L461).

Filings sort only by reporting period. For equal periods, upstream order survives, and financial merging keeps the first value unconditionally. The newer-filing-wins comment is therefore not true for same-period amendments.

**Reproduction:** Return two FY2025 filings, the original dated January with revenue 100, then an amendment dated February with revenue 200. `getEsefFinancials` returns **100** from January.

**Impact:** Results depend on upstream list order and can miss corrections for the same reporting period. Existing restatement tests cover a newer annual report's comparative, not amendments sharing the same period.

**Fix:** Define an explicit revision-order policy and use a reliable full timestamp/revision signal for equal periods. Do not discard timestamp precision before selection. Test reversed upstream order and same-period amendments.

### 11. P2 — ESEF EPS loses its unit

**Location:** [src/adapters/xbrlFilings.ts:364](../src/adapters/xbrlFilings.ts#L364).

`unitCode` accepts only a three-letter currency after removing the first namespace prefix. Compound per-share units are rejected even though basic/diluted EPS are supported concepts.

**Reproduction:** A `BasicEarningsLossPerShare` fact with unit `iso4217:GBP/xbrli:shares` returns value **2.5** with `unit: ""`.

**Impact:** The structured result loses both currency and the per-share dimension, making it ambiguous to downstream consumers.

**Fix:** Normalize supported compound units, for example to `GBP/shares`, and preserve or explicitly reject unsupported units. Add EPS-specific unit cases rather than using currency-only fixtures for every metric.

## Engineering assessment

Strengths worth retaining:

- Adapter-level fetch/env injection makes boundary failures cheap to reproduce without real credentials.
- Strict source compiler settings, substantial fixture coverage, real MCP transport tests, and explicit jurisdiction/resource documentation provide a useful foundation.
- Restricted-source checks and source-content warnings are deliberate. ZIP validation checks paths, sizes, CRCs, and malformed archives; the newer HTTP binary helper provides streaming limits and redirect controls.
- Existing partial-support explanations are more informative than generic empty results in many newer adapters.

The main maintainability constraint is the **7,817-line tool dispatcher** plus repeated download/rendering logic. The omitted NL route and uneven adoption of the bounded downloader are concrete consequences. A focused follow-up should centralize only repeated policies: exhaustive route selection, bounded retrieval, file-write behavior, and structured failure/completeness reporting. A wholesale adapter framework rewrite is unnecessary.

Additional validation gaps, separate from the reproduced defects:

- TypeScript is not pinned in the manifest/lockfile; `bunx tsc` resolves a compiler outside the frozen install. Pin it to make release checks reproducible.
- The CI Node 18/20/22 matrix runs most tests under Bun. Stdio launches Node, but the HTTP suite directly imports TypeScript under Bun. Run a fresh-bundle HTTP smoke under the actual supported Node versions.
- The stdio test reuses `dist/server.mjs` when present. CI rebuilds and reruns it, but a local `bun test` may exercise an older bundle.
- Live E2E is manual-only. Static fixtures cannot establish current host reachability or detect upstream layout drift. Add a bounded scheduled canary for supported, authorized sources with explicit degraded-status reporting.
- FileCache error handling and concurrent writes deserve follow-up: reads tolerate corruption, but `set` errors propagate through adapters despite the README's broader “a broken cache never breaks a lookup” promise. Direct writes are not atomic.

## Suggested remediation order

1. HTTP host/origin checks; safe PDF writes; streaming limits and body-lifetime deadlines.
2. ESEF null handling; truthful SEC failure reporting; amendment and EPS correctness; exhaustive non-US routing.
3. Adapter cache expiry; isolated package typing validation; pinned build tooling and runtime-specific checks.

Do not use a higher test count as the acceptance criterion. Each fix should demonstrate the failed contract at the boundary where users consume it.
